# UT 시나리오

## D-A · 검토 요청부터 병합까지

- **시트 00 — 요청 알림:** 첫날 Workspace에서 결제 버튼 변경 검토 요청을 확인한다. 오래된 이력을 기억하는 상황으로 시작하지 않는다.
- **시트 01 — Conflict Points:** 알림에서 `Place order button · Height & color`를 열고, 현재 구현과 디자인 기준을 살핀다.
- **시트 02 — History 근거:** History에서 해당 이슈 활동을 선택한다. 변경 리플레이가 그 체크포인트를 열고, 타임라인에 이슈 마커가 표시되는지 확인한다.
- **시트 03 — 병합 판단:** Overview로 돌아와 높이 44px와 기본 주요 색상 토큰을 적용하는 변경을 선택한다.
- **시트 04 — 의견 및 검토 요청:** 결정 근거를 댓글로 남기고 다른 검토자에게 검토 요청을 보낸다.
- **시트 05 — 순차 승인:** 요청 후 다른 검토자가 약 4초 뒤부터 순차 승인한다. 본인 승인은 직접 한다. 처리 중 변경이 생기면 기존 요청의 자동 승인은 취소된다.
- **시트 06 — 병합:** 모든 필수 승인과 검사를 확인한 뒤 병합한다.

## D-B · 디자인 비교

- **시트 07 — Workspace 디자인 비교:** Workspace의 `Design Compare`에서 결제 단계 시안 A/B/C/D를 비교한다.
- **시트 08 — 시안 선택:** 각 안에는 `Standard checkout`, `Progress and wallet`, `Saved card`, `Express pay and tax total`처럼 짧은 제목만 표시한다. 사람 이름은 표시하지 않는다.
- **시트 09 — 비교 결과:** 시안 사이의 차이는 디자인 선택지로 다룬다. 충돌 목록이나 충돌 알림에 올리지 않고, 충돌 검토/승인 흐름도 시작하지 않는다.

## 개발자 시나리오 · Mobile Nav Revamp

- **시트 10 — 프로젝트와 요청:** 개발 참여자가 있는 `Mobile Nav Revamp` 프로젝트에서 `Nav Icon / Size` 검토 요청 알림을 연다.
- **시트 11 — 변경 근거:** Conflict Points에서 아이콘 20px 구현과 디자인의 24px 기준을 확인한다. History에서 이 이슈 활동을 선택해 이전 구현과 충돌 마커를 확인한다.
- **시트 12 — 승인 및 병합:** 44px 터치 영역은 유지하는 변경임을 확인하고 검토자로서 직접 승인한다. 다른 검토자의 순차 승인이 끝나면 병합하고 History의 결과 체크포인트를 확인한다.

## 확인할 관찰 항목

- 검토 요청 알림에서 Conflict Points로 자연스럽게 진입하는가?
- History 활동 선택이 해당 변경 리플레이와 이슈 마커로 이어지는가?
- 참가자 본인 승인과 다른 검토자의 자동 순차 승인을 구분하는가?
- 검토 요청 이후 내용이 바뀌면 이전 요청의 자동 승인이 무효화되는가?
- 디자인 대안과 실제 디자인-코드 불일치를 구분하는가?
- 시트 번호가 `00`부터 순서대로 이어지는가?

자동 승인은 UT 데모 동작이다. 요청 후 내용이 바뀌면 예약된 승인은 취소되며, 수정된 내용으로 다시 검토 요청 또는 리마인드를 보내야 한다. 화면을 닫아도 워크스페이스 내 요청은 계속 진행된다.
